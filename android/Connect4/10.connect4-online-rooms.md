בסוף הפרק משתמש יוצר חדר כאדום, משתמש אחר מקבל את מושב הצהוב, ואחרים נכנסים כצופים. החדרים מופיעים בזמן אמת. הלוח מוצג בחדר אך עדיין לא מקבל מהלכי רשת.

זהו פרק ארוך שאפשר ללמד בכמה מפגשים: קודם חוזה החדר, אחר כך repository והאזנה, ולבסוף עסקאות וחיבור למסך. משלימים את המחלקות התלויות זו בזו לפני הבנייה; אין להעתיק את כל חבילת multiplayer מהפרויקט המוגמר.

## מה נשמר בענן?

כל חדר נמצא תחת `Connect4Rtdb/games/{pushId}`. השם הוא תווית; מפתח push הוא הזהות, ולכן מותר לשני חדרים להיקרא באותו שם. נשמרים `schemaVersion`, `name`, `playerRed`, `playerYellow`, `moves`, `createdAt`, `updatedAt`. בחדר חדש המושב הצהוב וההיסטוריה הם מחרוזות ריקות.

המצבים waiting / playing / finished נגזרים מנתוני החדר. לא שומרים גם לוח וגם תור וגם תוצאה שעלולים לסתור את ההיסטוריה. כבר עכשיו בודקים חדר שנכנס מהשרת לפני שמציגים אותו.

## כללי גישה לפני כתיבה

המורה משתמש ב־[קטע הכללים של פרק 10]({{ '/android/Connect4/downloads/10-room-rules.json' | relative_url }}). הוא מאפשר קריאה למשתמש מחובר, יצירת חדר שהיוצר הוא האדום, ותפיסה חד־פעמית של מושב צהוב בידי UID אחר. בשלב זה אין הרשאה להוסיף מהלכים.

{: .box-warning}
זהו קטע למיזוג תחת rules במסד המשותף, לא תחליף לכל הכללים. אין לפרסם את emulator.rules.json למסד חי. המורה בודק ב־emulator את המיזוג עם כללי האתר הקיימים, כולל הרשאות אב ו־wildcards. ביצוע השיעור אינו דורש פריסה מחדש של כללי פרויקטים אחרים.

קובצי ה־emulator, קטע הכללים וכלי המיזוג נמצאים גם בחבילת האימות של הפרק. תלמיד צריך להסביר מי רשאי ליצור ולתפוס מושב; אין די בכך שהכפתור מוסתר.

מאמתים גרסת סכימה, שם, מושבים שונים, היסטוריה ותאריכים. replay מפעיל כל עמודה דרך המנוע. אם מהלך אחד אסור, כל תמונת החדר נדחית; בשונה משמירה מקומית, לא מציגים קידומת כאילו היא החדר המשותף התקין.

גם בחדר ריק נדרש חוזה מלא. ההכנה ל־replay שימושית כאשר רשימת החדרים כוללת משחקים שכבר שוחקו על ידי אחרים.

```java
package com.example.connect4.multiplayer;

import com.example.connect4.core.GameAction;
import com.example.connect4.core.GameEngine;
import com.example.connect4.core.GameState;

/** Strict validation and deterministic replay for Firebase room data. */
public final class RoomValidation {
    public static final int SCHEMA_VERSION = 1;
    public static final int MAX_NAME_LENGTH = 60;
    public static final int MAX_MOVES = 42;

    private RoomValidation() {
    }

    /** Replays persisted moves and returns either a derived status or a safe validation error. */
    public static Result validate(RoomData room) {
        if (room == null) {
            return Result.invalid("Room data is missing");
        }
        if (room.getSchemaVersion() != SCHEMA_VERSION) {
            return Result.invalid("Unsupported room schema");
        }

        String name = room.getName();
        if (name == null || name.isEmpty() || name.length() > MAX_NAME_LENGTH
                || !name.equals(name.trim())) {
            return Result.invalid("Room name must be trimmed and contain 1-60 characters");
        }

        String red = room.getPlayerRed();
        String yellow = room.getPlayerYellow();
        String moves = room.getMoves();
        if (red == null || red.isEmpty()) {
            return Result.invalid("Room has no Red player");
        }
        if (yellow == null) {
            return Result.invalid("Room has no Yellow seat field");
        }
        if (!yellow.isEmpty() && yellow.equals(red)) {
            return Result.invalid("Red and Yellow must be different users");
        }
        if (moves == null || moves.length() > MAX_MOVES || !moves.matches("[0-6]*")) {
            return Result.invalid("Move history must contain at most 42 columns from 0 to 6");
        }
        if (yellow.isEmpty() && !moves.isEmpty()) {
            return Result.invalid("A waiting room cannot contain moves");
        }
        if (room.getCreatedAt() <= 0 || room.getUpdatedAt() < room.getCreatedAt()) {
            return Result.invalid("Room timestamps are missing or out of order");
        }

        GameEngine engine = new GameEngine();
        for (int index = 0; index < moves.length(); index++) {
            int column = moves.charAt(index) - '0';
            if (!engine.apply(new GameAction(column))) {
                return Result.invalid("Move history is illegal at move " + (index + 1));
            }
        }

        GameState state = engine.snapshot();
        RoomStatus status;
        if (yellow.isEmpty()) {
            status = RoomStatus.WAITING;
        } else if (state.isTerminal()) {
            status = RoomStatus.FINISHED;
        } else {
            status = RoomStatus.PLAYING;
        }
        return Result.valid(state, status);
    }

    /** Immutable result of validating a Firebase room payload. */
    public static final class Result {
        private final GameState state;
        private final RoomStatus status;
        private final String error;

        private Result(GameState state, RoomStatus status, String error) {
            this.state = state;
            this.status = status;
            this.error = error;
        }

        private static Result valid(GameState state, RoomStatus status) {
            return new Result(state, status, null);
        }

        private static Result invalid(String error) {
            return new Result(null, null, error);
        }

        /** Reports whether all schema, seat, timestamp, and replay checks passed. */
        public boolean isValid() {
            return error == null;
        }

        /** Returns the replayed state, or {@code null} when validation failed. */
        public GameState getState() {
            return state;
        }

        public RoomStatus getStatus() {
            return status;
        }

        public String getError() {
            return error;
        }
    }
}
```

עבדו במחלקה לפי האחריות של כל קבוצת מתודות:

1. הבנאי מחבר Auth ומסד ומייצר reference רק לאוסף החדרים.
2. `subscribeLobby` ו־`subscribeRoom` מפרסמות נתונים שעברו בדיקה ומחזירות Subscription להסרה. `getRoom` קוראת חדר אחד.
3. `createRoom` מקבלת push key וכותבת את כל החדר בפעולה אחת. ממתינים להשלמת הכתיבה לפני הכרזה על יצירה.
4. `joinRoom` בודקת מידע התחלתי, ואז `runJoinTransaction` בודקת שוב את המושב בתוך transaction. שתי בקשות עשויות להתחיל יחד; רק אחת יכולה לתפוס את צהוב. השנייה מקבלת את תפקידה המעודכן כצופה.
5. פעולות ממתינות מזוהות לפי מפתח חדר ב־repository שנשמר ב־Session; לחיצה כפולה אינה יוצרת בקשה זהה נוספת.

## מריצים ובודקים

1. עם שני חשבונות בדיקה, צרו חדר במכשיר אחד ובדקו שהוא מופיע בלובי של השני.
2. היוצר הוא Red; המשתמש השני הוא Yellow. שלישי הוא Spectator.
3. נסו לתפוס את הצהוב בשני לקוחות בו־זמנית: בדיוק אחד מקבל Yellow.
4. חזרו ללובי ופתחו את אותו החדר: התפקיד לא משתנה. שם זהה לחדר אחר אינו מחליף את המפתח.
5. הלוח בחדר עדיין אינו מקבל נגיעות. אל תעקפו זאת על ידי הפעלה מקומית של המנוע.

בדיקת Android יוצרת שלושה משתמשים ב־emulator ובודקת תפיסה מתחרה ותפקידים. בדיקות הכללים בודקות יצירה, בעלות והיעדר פגיעה בהרשאות המייצגות של היישומים האחרים. אלה בדיקות מקומיות, לא בדיקת פריסה חיה.
