## What is important in our economy

- `Circles` is a spendable balance, so it decreases after a purchase.
- `Lifetime` measures how many circles have ever been collected, so buying does not change it.
- The next price depends on how many Pushers are already owned.
- You cannot buy if the balance is less than the price.
- Every purchase is saved immediately, like the collections from the previous chapters.

## 1. Calculate the next price

Open `GameProgress.java` and add a constant:

```java
static final long FIRST_PUSHER_PRICE = 64;
```

The prices are:

```text
64, 128, 256, 512, ...
```

Each price is twice the previous price. If `pusherCount` is the number of Pushers already bought, the price is:

```text
64 × 2ᵖᵘˢʰᵉʳᶜᵒᵘⁿᵗ
```

For integers, shifting left by one bit multiplies by 2. Add:


```java
/**
 * Calculates the price for a given number of owned Pushers.
 *
 * @param pusherCount number of Pushers already owned
 * @return the next price, or {@link Long#MAX_VALUE} before overflow
 * @throws IllegalArgumentException if pusherCount is negative
 */
static long priceForPusherCount(int pusherCount) {
    if (pusherCount < 0) {
        throw new IllegalArgumentException("pusherCount cannot be negative");
    }
    if (pusherCount >= 57) {
        return Long.MAX_VALUE;
    }
    return FIRST_PUSHER_PRICE << pusherCount; // bit shift multiplication
}

/**
 * Returns the price that follows the number of Pushers already owned.
 *
 * @return the price of the next Pusher
 */
public long getNextPusherPrice() {
    return priceForPusherCount(pusherCount);
}
```

Why stop at 57? `long` has a limited range. After enough multiplications, the result would overflow and become negative. Instead of allowing a negative price, we return the largest price that `long` can represent. Later, we could replace just this method with a price function that grows more slowly.

### Buy ==(new similar method)==

```java
/**
 * Buys one Pusher when the balance can cover its current price.
 *
 * @return true when the purchase succeeds; false when the balance is too low
 */
public boolean buyPusher() {
    long price = getNextPusherPrice();
    if (circlesBalance < price) {
        return false;
    }

    circlesBalance -= price;
    pusherCount++;

    preferences.edit()
            .putLong(CIRCLES_BALANCE_KEY, circlesBalance)
            .putInt(PUSHER_COUNT_KEY, pusherCount)
            .apply();
    return true;
}
```

Buying only decreases the balance.

</div>

Before `buyPusher()`, also add a method the screen can use to decide whether the button should be enabled:

```java
/**
 * Checks affordability without changing the saved progress.
 *
 * @return true when the balance can cover the next Pusher's price
 */
public boolean canBuyPusher() {
    return circlesBalance >= getNextPusherPrice();
}
```

`buyPusher()` checks the condition again, even though the screen will also check it. The data class must not trust that a particular screen has hidden or disabled a button.

{: .box-success}
After buying the first Pusher, 64 circles are deducted from the balance but `Lifetime` remains unchanged. The next price immediately becomes 128.

## 5. Display a purchase dialog

In `MainActivity.java` add import:

```java
import androidx.appcompat.app.AlertDialog;
```

Connect the button in `onCreate`:

```java
binding.shopButton.setOnClickListener(view -> showPusherShop());
```

And add the method:

```java
/**
 * Opens the shop and handles the purchase of one Pusher.
 */
private void showPusherShop() {
    AlertDialog dialog = new MaterialAlertDialogBuilder(this)
            .setTitle(R.string.shop_title)
            .setMessage(getString(
                    R.string.shop_message,
                    gameProgress.getPusherCount(),
                    gameProgress.getCirclesBalance(),
                    gameProgress.getNextPusherPrice()
            ))
            .setNegativeButton(R.string.close, null)
            .setPositiveButton(R.string.hire_pusher, null)
            .create();

    dialog.setOnShowListener(ignored -> {
        dialog.getButton(AlertDialog.BUTTON_POSITIVE)
                .setEnabled(gameProgress.canBuyPusher());
        dialog.getButton(AlertDialog.BUTTON_POSITIVE).setOnClickListener(view -> {
            if (gameProgress.buyPusher()) {
                showProgress();
                Toast.makeText(this, R.string.pusher_hired, Toast.LENGTH_SHORT).show();
                dialog.dismiss();
            }
        });
    });

    dialog.show();
}
```

We create the positive button using the Builder, but only change the click action after the dialog is displayed. At this stage you can get the button itself, disable it when there are not enough circles, and close the dialog only after a successful purchase.

No additional Activity or Fragment is needed: the shop is a small interaction over the game screen, so a dialog is enough and keeps the work manageable.

## 6. Checking the price function

{: .box-note}
**Which file do you add a test to?** A pure Java test, which does not require Android, a device or `Context`, is added to `ExampleUnitTest.java` in the `(test)` folder. A test that needs the Android environment — for example, creating `GameProgress` with a real `Context` or testing `SharedPreferences` — is added to `ExampleInstrumentedTest.java` in the `(androidTest)` folder and run on the device or emulator.

The method `priceForPusherCount()` only calculates and returns a number, so its test does not need Android. In Android Studio, open **app > kotlin+java > com.example.collectcircles (test) > ExampleUnitTest**, and add:

```java
/**
 * Verifies that prices double and stop safely before long overflow.
 */
@Test
public void pusherPricesDoubleWithoutOverflowing() {
    assertEquals(64, GameProgress.priceForPusherCount(0));
    assertEquals(128, GameProgress.priceForPusherCount(1));
    assertEquals(256, GameProgress.priceForPusherCount(2));
    assertEquals(Long.MAX_VALUE, GameProgress.priceForPusherCount(57));
}
```

Run one test and build:

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug
```

## 7. Manual inspection

1. With a balance less than 64, open Shop. Make sure the price is 64 and the Hire button is disabled.
2. Collect until the balance is at least 64. This can be done in short games or in Auto mode.
3. Open Shop and buy Pusher. Check that 64 dropped from Circles, Pushers went up to 1 and Lifetime didn't change.
4. Open the store again. The next price should be 128.
5. Close and open the application. The number of Pushers and the balance should be maintained.
6. Check that Local, Invite, and Shop fit on one row and each button responds to clicks.
