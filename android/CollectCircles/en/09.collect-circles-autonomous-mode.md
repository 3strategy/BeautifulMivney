{: .box-note}
In the previous chapter, circles began accumulating across multiple games. Now add a second mode: **Auto** has no finish line, and new circles keep appearing, up to a maximum of 12 on the board. You can still drag each circle manually, and each collection still updates both counters.

{: .box-warning}
This chapter is significantly longer than the previous chapters. Take your time.


## The result we want to see

- In normal mode, Start runs the same short game we already built.
- Turning Auto on stops the short round and immediately starts an endless board with three circles.
- A new circle appears about once every five seconds, but there will never be more than 12 circles on the screen.
- Turning Auto off returns to the screen waiting for Start.
- The choice persists: if you close the app with Auto on, it returns to that mode next time.

{: .box-warning}
"Endless" does not mean creating infinitely many objects. The game can continue indefinitely because collected circles are removed and new ones are created, while the number present at any moment stays limited.

## 1. Save the game mode too

Open `GameProgress.java`. Add a key and a field:

```java
// Key used to persist the selected game mode in SharedPreferences.
private static final String AUTONOMOUS_MODE_KEY = "autonomous_mode";

// Cached mode used by the current screen.
private boolean autonomousMode;
```

Load it at the end of the constructor. The default is `false`, so an existing installation initially opens in the familiar game mode:

```java
autonomousMode = preferences.getBoolean(AUTONOMOUS_MODE_KEY, false);
```

Add getter and setter:

```java
/**
 * Returns the game mode currently selected by the player.
 */
public boolean isAutonomousMode() {
    return autonomousMode;
}

/**
 * Updates the selected mode and saves it for the next app launch.
 */
public void setAutonomousMode(boolean autonomousMode) {
    this.autonomousMode = autonomousMode;
    preferences.edit()
            .putBoolean(AUTONOMOUS_MODE_KEY, autonomousMode)
            .apply();
}
```

{: .box-note}
A comment beginning with `/**` is Javadoc. Android Studio shows it to callers, and tags such as `@param`, `@return`, and `@throws` document the method’s contract where it is needed.


The setter updates both the field used by the current screen and the saved value loaded next time.

Now add the model’s update loop:

```java
/**
 * Updates circle spawning in Auto mode using elapsed time and the board limit.
 *
 * @param elapsedSeconds The time elapsed since the previous update, in seconds
 * @param boardWidth The width of the game board in pixels
 * @param boardHeight The height of the game board in pixels
 * @param circleColor The color of the new circles
 */
public void update(double elapsedSeconds, float boardWidth,
                   float boardHeight, int circleColor) {
    if (!autonomous) {
        return;
    }

    spawnProgress += elapsedSeconds * AUTONOMOUS_SPAWN_RATE;
    while (spawnProgress >= 1.0 && circles.size() < MAX_CIRCLE_COUNT) {
        createCircles(circles.size() + 1, boardWidth, boardHeight, circleColor);
        spawnProgress -= 1.0;
    }

    if (circles.size() == MAX_CIRCLE_COUNT) {
        spawnProgress = Math.min(spawnProgress, 1.0);
    }
}
```

`spawnProgress` is a fractional accumulator. At a rate of `0.20`, it gains one fifth of a circle each second. After five seconds, it reaches 1 and a whole circle can be created. When the board is full, we do not accumulate a "debt" of circles that would flood the screen as soon as space becomes available.

Add a small method that will help the tests:

```java
/**
 * Returns the number of circles currently on the board.

    return circles.size();
}
```

And finally make sure that an autonomous game never reports that it's finished:

+ */

-    return circles.isEmpty();

## 4. Add a frame loop to `GameBoardView`

`Canvas` draws only when Android calls `onDraw`. To make circles appear even without touch input, request another frame using `postOnAnimation()`.

Add import:

```java
import android.os.SystemClock;
```

Add fields:

```java
// True while the Auto frame callback should keep scheduling itself.
private boolean autonomousRunning;
// Timestamp of the previous frame, used to measure real elapsed time.
private long previousFrameMillis;
```

Add a Runnable that calculates the actual elapsed time:

```java
// Repeats once per display frame while Auto mode is running.
private final Runnable autonomousFrame = new Runnable() {
    /**
     * Advances the model by one frame and requests the next drawing pass.
     */
    @Override
    public void run() {
        if (!autonomousRunning || game == null) {
            return;
        }

        long nowMillis = SystemClock.elapsedRealtime();
        double elapsedSeconds = (nowMillis - previousFrameMillis) / 1000.0;
        previousFrameMillis = nowMillis;

        game.update(elapsedSeconds, getWidth(), getHeight(), color(R.color.circle_green));
        invalidate();
        postOnAnimation(this);
    }
};
```

Change the normal game creation so that it stops a previous loop, uses the helpers we'll add right after, and passes `false` to the constructor:

Add the autonomous mode methods:

```java
/**
 * Creates a fresh Auto game and starts its frame loop.
 */
public void startAutonomousGame() {
    if (getWidth() == 0 || getHeight() == 0) {
        return;
    }

    float targetRadius = calculateTargetRadius();
    game = createGame(targetRadius, true);
    resumeAutonomousGame();
    invalidate();
}

/**
 * Resumes frame updates without replacing the current game.
 */
public void resumeAutonomousGame() {
    if (game == null || autonomousRunning) {
        return;
    }
    autonomousRunning = true;
    previousFrameMillis = SystemClock.elapsedRealtime();
    postOnAnimation(autonomousFrame);
}

/**
 * Pauses frame updates while preserving the current game.
 */
public void pauseAutonomousGame() {
    stopAutonomousFrames();
}

/**
 * Stops all updates and removes the current game from the board.
 */
public void clearGame() {
    stopAutonomousFrames();
    game = null;
    invalidate();
}

/**
 * Cancels the scheduled callback so only one Auto loop can exist.
 */
private void stopAutonomousFrames() {
    autonomousRunning = false;
    removeCallbacks(autonomousFrame);
}
```

Also extract the radius calculation removed from `startNewGame()` into a method, so both modes use exactly the same target size:

```java
/**
 * Calculates the target size shared by timed and Auto games.
 */
private float calculateTargetRadius() {
    return Math.min(
            dp(TARGET_RADIUS_DP),
            Math.min(getWidth(), getHeight()) / 5f
    );
}
```

## 5. Connect the switch in `MainActivity`

After `showProgress()` in `onCreate`, set the switch state **before** attaching its listener. This prevents the initial load from being treated as a user change:

```java
// Restore the saved switch position before attaching its listener.
binding.autonomousSwitch.setChecked(gameProgress.isAutonomousMode());
// Build the screen that matches the restored mode.
showSelectedGameMode();
```

Add a listener next to the listeners of the buttons:

```java
// Persist mode changes and immediately rebuild the game screen.
binding.autonomousSwitch.setOnCheckedChangeListener((button, enabled) -> {
    gameProgress.setAutonomousMode(enabled);
    showSelectedGameMode();
});
```

And add the method that switches between the modes:

```java
/**
 * Stops the previous mode and configures the selected game mode.
 */
private void showSelectedGameMode() {
    // Removes every queued execution of this exact Runnable from the View's message queue.
    // This stops future timer updates but does not delete or disable timerUpdate,
    // so the same Runnable can be started again later with timerUpdate.run().
    binding.elapsedTimeText.removeCallbacks(timerUpdate);
    gameRunning = false;

    if (gameProgress.isAutonomousMode()) {
        binding.startButton.setEnabled(false);
        binding.elapsedTimeText.setText(R.string.autonomous_time);
        // Wait until GameBoardView has valid width and height measurements.
        binding.gameBoard.post(() -> {
            if (gameProgress.isAutonomousMode()) {
                binding.gameBoard.startAutonomousGame();
            }
        });
    } else {
        binding.startButton.setEnabled(true);
        binding.elapsedTimeText.setText(R.string.elapsed_time_initial);
        binding.gameBoard.clearGame();
    }
}
```

Check `isAutonomousMode()` again because the Runnable executes only after the View has been measured. If the user turns Auto off in that brief interval, the outdated request must not accidentally start an autonomous game.

In `onStart`, resume the normal game timer or the Auto loop:

```diff
+/**
+ * Resumes the update loop that belongs to the selected game mode.
+ */
 @Override
 protected void onStart() {
     super.onStart();
-    if (gameRunning) {
+    // Resume only the loop that belongs to the selected game mode.
+    if (gameProgress.isAutonomousMode()) {
+        binding.gameBoard.resumeAutonomousGame();
+    } else if (gameRunning) {
         binding.elapsedTimeText.removeCallbacks(timerUpdate);
         timerUpdate.run();
     }

```

In `onStop`, stop both:

```java
/**
 * Stops both update loops while the Activity is not visible.
 */
@Override
protected void onStop() {
    binding.elapsedTimeText.removeCallbacks(timerUpdate);
    binding.gameBoard.pauseAutonomousGame();
    super.onStop();
}
```

Stopping the frames in the background does not cancel the saved Auto mode. It only prevents the screen from drawing when it cannot be seen. In the offline-progress chapter, we will calculate progress for this time without drawing thousands of unnecessary frames.

## 7. Manual inspection

1. Open the app in normal mode. Check that Start still creates five circles and the timer works.
2. Activate Auto. Start should be disabled, the time label should show `Time: autonomous`, and three circles should appear immediately.
3. Wait about five seconds and make sure that another circle appears without touching the screen.
4. Drag circles into the target. Circles and Lifetime should increase without a completion dialog appearing.
5. Leave the game open until the board reaches 12 circles. Check that it never exceeds that limit.
6. Turn Auto off. The board should clear and Start should become available again.
7. Turn Auto on, close the app, and reopen it. The switch setting and autonomous board should return.
8. Check that the notification buttons still fit on their row without covering the board.
