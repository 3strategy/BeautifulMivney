## מה נלמד

- כיצד מצהירים על `POST_NOTIFICATIONS` ומבקשים אותה בזמן ריצה ב־Android 13 ומעלה.
- מהו `NotificationChannel` ומדוע כל התראה משתייכת לערוץ.
- כיצד בונים `Notification` ומוסרים אותה ל־Android בעזרת `notify`.

לא נשתמש בתזמון או בעבודה ברקע. אין כאן `AlarmManager`,‏ `JobScheduler` או `WorkManager`:
הלחיצה היא האירוע שמציג את ההתראה מיד.

## 3. יוצרים את מחלקת העזר `Notifications`

בחלון **Project**, עברו אל:

`app > java > com.example.collectcircles`

לחצו לחיצה ימנית על החבילה **`com.example.collectcircles`**, בחרו
**New > Java Class**, הקלידו `Notifications` ובחרו **Class**. Android Studio ייצור בדיוק את:

`app/src/main/java/com/example/collectcircles/Notifications.java`

החליפו את תוכן הקובץ בקוד הבא:

```java
package com.example.collectcircles;

import android.app.Notification;
import android.app.NotificationChannel;
import android.app.NotificationManager;
import android.content.Context;

public final class Notifications {

    private static final String CHANNEL_ID = "circle_invitations";
    private static final int NOTIFICATION_ID = 1;

    private Notifications() {
        // זוהי מחלקת עזר בלבד. אין צורך ליצור ממנה אובייקטים.
    }

    public static void createChannel(Context context) {
        NotificationManager manager = context.getSystemService(NotificationManager.class);

        // כל התראה חייבת להשתייך לערוץ. יצירת ערוץ שכבר קיים אינה יוצרת כפילות,
        // ולכן בטוח לבצע את הפעולה לפני כל הצגה. חשיבות HIGH מאפשרת למערכת
        // להציג את ההתראה באופן בולט, בהתאם להגדרות שבחר המשתמש במכשיר.
        NotificationChannel channel = new NotificationChannel(
                CHANNEL_ID,
                context.getString(R.string.notification_channel_name),
                NotificationManager.IMPORTANCE_HIGH
        );
        channel.setDescription(
                context.getString(R.string.notification_channel_description)
        );
        manager.createNotificationChannel(channel);
    }

    public static void show(Context context) {
        createChannel(context);
        NotificationManager manager = context.getSystemService(NotificationManager.class);

        // ה-Builder רק מתאר את ההתראה. הקריאה notify היא הפעולה שמוסרת אותה
        // למערכת Android, ומאותו רגע המערכת אחראית להציג אותה למשתמש.
        Notification notification = new Notification.Builder(context, CHANNEL_ID)
                .setSmallIcon(R.drawable.ic_launcher_foreground)
                .setContentTitle(context.getString(R.string.notification_title))
                .setContentText(context.getString(R.string.notification_text))
                .build();

        manager.notify(NOTIFICATION_ID, notification);
    }
}
```

`CHANNEL_ID` הוא המזהה הפנימי הקבוע. שם הערוץ והתיאור הם הטקסטים שהמשתמש רואה בהגדרות.
יצירת ערוץ שכבר קיים בטוחה; Android אינו יוצר עותק נוסף. `IMPORTANCE_HIGH` מאפשר הצגה
בולטת, אבל המשתמש עדיין רשאי לשנות את הגדרות הערוץ.

שימוש חוזר ב־`NOTIFICATION_ID` מעדכן את אותה התראה במקום למלא את מגירת ההתראות בעותקים.

<div markdown="1" class="box-note">

**חשוב להפריד בין שתי פעולות שמתרחשות אצלנו באותה לחיצה.** הכפתור `LocalNotif` גם מתחיל
את תהליך בקשת ההרשאה וגם, לאחר שההרשאה קיימת, מבקש להציג התראה. אלה אינן אותה פעולה:

1. `notificationPermissionLauncher.launch(...)` פותחת חלון מערכת ומבקשת מן המשתמש רשות
   להציג התראות. רק קוד שרץ באפליקציה כשהמשתמש משתמש בה יכול לפתוח את החלון הזה.
2. `Notifications.show(...)` יוצרת התראה ומוסרת אותה ל־Android. היא תצליח להציג אותה רק אם
   ההרשאה כבר ניתנה.

אותה הרשאה חלה גם על התראות שמגיעות מאוחר יותר מ־FCM. אם ב־Android 13 ומעלה האפליקציה מעולם
לא ביקשה מן המשתמש `POST_NOTIFICATIONS`, או שהמשתמש דחה אותה, שרת החברה עדיין יכול לשלוח
הודעת FCM והמכשיר אף עשוי לקבל אותה — אבל Android לא יציג אותה כהתראה למשתמש. השרת וה־curl
אינם יכולים לפתוח מרחוק את חלון ההרשאה או לאשר אותו במקום המשתמש.

</div>

ב־Android 13 ומעלה הזרימה בלחיצה הראשונה היא:

```text

```

בפעמים הבאות ההרשאה כבר קיימת ולכן ההצגה מיידית. ב־Android 12 ומטה אין חלון הרשאה זה.

## היכן מבקשים הרשאה באפליקציה שאין בה כפתור LocalNotif?

באפליקציה אמיתית אין צורך בכפתור שמציג התראה מקומית. עדיין חייב להיות **רגע בצד האפליקציה**
שבו מסבירים למשתמש מדוע ההתראות מועילות ומפעילים את
`notificationPermissionLauncher`. המקום המתאים תלוי במוצר:

- במסך היכרות, לאחר הסבר קצר כגון "נודיע לך כשמגיעה הודעה חדשה" וכפתור **הפעלת התראות**;
- כאשר המשתמש מפעיל לראשונה תכונה שתלויה בהתראות, למשל תזכורות, משלוחים או הודעות חדשות;
- במסך Settings של האפליקציה, כאשר המשתמש מפעיל מתג **קבלת התראות**;
- לאחר כניסה לחשבון, אם רק משתמש מחובר יכול לקבל את ההתראות התקופתיות של החברה.

מומלץ לא לפתוח את חלון המערכת מיד וללא הקשר בפתיחה הראשונה. קודם מציגים הסבר קצר במסך
האפליקציה, ורק בעקבות בחירה ברורה של המשתמש מפעילים את בקשת המערכת. כך המשתמש מבין מה יקבל
ומדוע כדאי לאשר.

הזרימה באפליקציה שמקבלת התראות תקופתיות משרתי חברה תהיה:

```text
פתיחת האפליקציה בפעם הראשונה
→ הסבר על יתרון ההתראות
→ המשתמש בוחר "הפעלת התראות"
→ בקשת POST_NOTIFICATIONS ואישור המשתמש
→ רישום המכשיר ב-FCM ושמירת המנוי
→ בעתיד השרת שולח הודעות גם כשהמסך אינו פתוח
→ Android מציג אותן באמצעות ההרשאה שכבר ניתנה
```

{: .box-warning}
הרשאה היא החלטה של המשתמש במכשיר, ואילו רישום ל־FCM הוא חיבור טכני לשירות ההודעות. צריך את
שניהם: מנוי FCM בלי הרשאה יכול לקבל מידע בלי להציג התראה; הרשאה בלי רישום FCM מאפשרת להציג
התראות מקומיות, אבל אין לשרת כתובת או topic שדרכם ישלח הודעה. בפרק 6 נוסיף את צד ה־FCM.

## 5. בודקים את השלב

1. בצעו **Build > Make Project** והפעילו את היישום.
2. לחצו `LocalNotif`.
3. ב־Android 13 ומעלה אשרו את בקשת ההתראות.
4. ודאו שמופיעה התראה בשם **Collect Circles** עם הטקסט
   **Come collect circles with me!**.
5. לחצו שוב וודאו שההתראה מתעדכנת מיד.

אם דחיתם את ההרשאה, היישום יציג Toast ולא יוכל להציג התראה. אפשר לאשר אותה דרך הגדרות
היישום במכשיר ולנסות שוב.

{: .box-success}
הטלפון כבר ביקש הרשאת התראות ויכול להציג התראה מקומית. בפרק 6 נרשום אותו לשני נושאי FCM;
גם ההתראות שמגיעות מן השרת כפופות **לאותה הרשאה**.
