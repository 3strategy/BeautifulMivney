{: .box-note}
המטרה בשלב הזה היא לא לכתוב מחדש את כל האפליקציה. מפעילים `View Binding`, מסנכרנים Gradle, ואז מחליפים בהדרגה קריאות `findViewById` בגישה ישירה דרך אובייקט `binding`.

בסוף השלב הזה נרצה לראות:

1. `viewBinding = true` מוגדר במודול `app`.
2. Android Studio מזהה מחלקות כמו `ActivityLoginBinding`.
3. לפחות מסך אחד, למשל `LoginActivity`, כבר עובד בלי `findViewById`.
4. שאר המסכים נשארים תקינים ואפשר להמיר אותם בהמשך בקצב מבוקר.

---

## שלב 1 - הפעלת View Binding ב־Gradle

פתחו את קובץ המודול:

- `app/build.gradle.kts`

בתוך הבלוק `android`, הוסיפו:

```diff
 android {
     namespace = "com.example.tictacmenu"
     compileSdk {
         version = release(36)
     }
 
+    buildFeatures {
+        viewBinding = true
+    }
+
     defaultConfig {
         applicationId = "com.example.tictacmenu"
         ...
     }
 }
```

אם כבר קיים אצלכם בלוק `buildFeatures`, אל תיצרו בלוק שני. הוסיפו רק את השורה:

```kotlin
viewBinding = true
```

{: .box-success}
אחרי העריכה חובה לבצע `Sync Now` / `Sync Project with Gradle Files`. רק אחרי הסנכרון Android Studio יוצר את מחלקות ה־Binding.

{: .box-warning}
אם `ActivityLoginBinding` מופיע באדום מיד אחרי העריכה, זה בדרך כלל לא אומר שהקוד שגוי. קודם מריצים Gradle Sync. אם זה עדיין אדום, בודקים ששם קובץ ה־XML באמת `activity_login.xml` ושאתם מייבאים את ה־package הנכון.

## שלב 2 - להבין את השמות שנוצרים

`View Binding` יוצר מחלקת Java עבור כל קובץ layout תחת `res/layout`.

דוגמאות נפוצות:

| קובץ XML | מחלקת Binding |
| --- | --- |
| `activity_login.xml` | `ActivityLoginBinding` |
| `activity_menu.xml` | `ActivityMenuBinding` |
| `fragment_home.xml` | `FragmentHomeBinding` |

גם מזהי ה־Views הופכים לשדות על `binding`.

| id ב־XML | גישה בקוד |
| --- | --- |
| `@+id/main` | `binding.main` |
| `@+id/cBstayconnect` | `binding.cBstayconnect` |
| `@+id/drawer_layout` | `binding.drawerLayout` |
| `@+id/navigation_view` | `binding.navigationView` |

{: .box-note}
ב־Java השמות נוצרים לפי ה־id. אם משנים id ב־XML, הקוד שמשתמש בשם הישן יישבר בזמן קומפילציה. זה טוב: השגיאה מתגלה מוקדם במקום להפוך לקריסה בזמן ריצה.

## שלב 4 - איך ממשיכים למסכים אחרים

אל תנסו להמיר את כל הפרויקט במכה אחת. בחרו Activity אחד, בנו והריצו, ואז עברו לבא.

הדפוס הקבוע בכל `Activity` הוא:

```diff
-setContentView(R.layout.activity_something);
+binding = ActivitySomethingBinding.inflate(getLayoutInflater());
+setContentView(binding.getRoot());
```

ואז מחליפים:

```diff
-drawerLayout = findViewById(R.id.drawer_layout);
-MaterialToolbar toolbar = findViewById(R.id.toolbar);
-NavigationView navigationView = findViewById(R.id.navigation_view);
+drawerLayout = binding.drawerLayout;
+MaterialToolbar toolbar = binding.toolbar;
+NavigationView navigationView = binding.navigationView;
```

במסך המשחק אפשר להמיר בהדרגה. לדוגמה, במקום:

```diff
-EditText ipEdit = findViewById(R.id.editServerIP);
+EditText ipEdit = binding.editServerIP;
```

אם יש לולאות שמקבלות `id` ומבצעות `findViewById(id)`, מותר להשאיר אותן לשלב מאוחר יותר. המטרה כאן היא מעבר מדורג, לא ריפקטור גדול.

## נוחות שנרוויח בהמשך

כשנתחיל להוסיף יותר UI, Firebase, תפריטים, ו־Fragments, `binding` יחסוך הרבה עבודה שחוזרת על עצמה:

1. **Autocomplete אמיתי:** כותבים `binding.` ורואים את כל ה־Views של המסך.
2. **פחות casting:** אין צורך להמיר ידנית `View` ל־`Button`, `EditText`, `NavigationView` וכדומה.
3. **שגיאות מוקדמות:** אם מחקתם או שיניתם id ב־XML, הקוד נשבר בקומפילציה ולא בזמן ריצה.
4. **מסכי Login נוחים יותר:** בשלבי Firebase הבאים נוכל לקרוא `binding.eTemail`, `binding.eTpass`, `binding.btnGoogleSignIn` בלי לחפש אותם ידנית.
5. **Drawer נקי יותר:** `MenuActivity` נהיה קריא יותר עם `binding.drawerLayout`, `binding.toolbar`, ו־`binding.navigationView`.
6. **Fragments בטוחים יותר:** גם בפרגמנטים משתמשים ב־binding, אבל שם חייבים לנקות אותו ב־`onDestroyView`.

<details markdown="1">
<summary><strong>דפוס קצר ל־Fragment</strong></summary>

ב־Fragment ה־View יכול להיהרס לפני שה־Fragment עצמו נהרס. לכן לא משאירים binding חי אחרי `onDestroyView`.

```java
private FragmentHomeBinding binding;

@Override
public View onCreateView(LayoutInflater inflater, ViewGroup container, Bundle savedInstanceState) {
    binding = FragmentHomeBinding.inflate(inflater, container, false);
    return binding.getRoot();
}

@Override
public void onDestroyView() {
    super.onDestroyView();
    binding = null;
}
```

</details>

## תקלות נפוצות

{: .box-warning}
`ActivityLoginBinding` לא מזוהה:

- ודאו שביצעתם Gradle Sync אחרי `viewBinding = true`.
- ודאו שהקובץ נמצא תחת `app/src/main/res/layout/activity_login.xml`.
- ודאו שהייבוא הוא `com.example.tictacmenu.databinding.ActivityLoginBinding` או ה־package שלכם.

{: .box-warning}
שדה מסוים לא קיים על `binding`:

- בדקו את ה־id המדויק ב־XML.
- אם ה־id כולל underscore, השם בקוד יהיה בדרך כלל camelCase, למשל `drawer_layout` -> `drawerLayout`.
- אם הרכיב נמצא רק בגרסת layout מסוימת, למשל רק ב־`layout-land`, ייתכן שהשדה יהיה nullable ותצטרכו לבדוק `null`.

{: .box-note}
אפשר לגרום ל־View Binding להתעלם מקובץ layout מסוים בעזרת `tools:viewBindingIgnore="true"` על ה־root של ה־XML, אבל בשלב הזה בדרך כלל אין צורך בזה.
